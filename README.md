CS255 System Analysis and Design

This repository showcases my work in system analysis and design through two core milestones completed for the DriverPass platform: the Business Requirements Document (Project One) and the System Design Document (Project Two). Together, these artifacts demonstrate my ability to collect, interpret, and convert customer needs into structural software engineering specifications.

**Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?**

The DriverPass project involved designing a secure, centralized management platform for a driving school to replace manual processes with an automated system. The platform was designed to support students, instructors, secretaries, and administrators by providing features such as online registration, package purchases, practice exams, lesson scheduling, performance tracking, calendar management, reporting, and security administration. To ensure efficient and accurate operations, the system also integrated with external services, including the DMV  and a third-party payment gateway for secure payment processing.

**What did you do particularly well?**

I think I did well in creating the UML use case and activity diagrams, which clearly illustrated interactions among students, instructors, secretaries, and administrators. The diagrams effectively defined user roles, system processes, and secure access controls while keeping the overall design organized and easy to understand.

**If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?**

Looking back at my work, one area I would improve is how I handled scheduling conflicts within the system. My diagrams show the basic lesson booking process, but they don't fully account for situations where multiple users try to reserve the same time slot at the same time. If I were revising the project, I would add more detail around conflict resolution and database validation to prevent double bookings and ensure a smoother user experience. This would make the system feel more realistic and better prepared for actual use.

**How did you interpret the user’s needs and implement them into your system design? Why is it so important to consider the user’s needs when designing?**

I interpreted the client's needs by breaking down the interview notes and focusing on how each user would interact with the system. This helped turn business requirements into practical system features.  Considering user needs is important because even a well-designed system will fail if it is difficult to use. By keeping students, instructors, and office staff in mind throughout the design process, I will be able to create a system that is both functional and easy to use, reducing errors and improving the overall experience.

**How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system?**

My approach to software design is very visual and focused on understanding requirements before writing any code. I like using the tools like Lucidchart to map out workflows, organize ideas, and catch potential problems early. The DriverPass project showed me how useful diagrams can be for turning client requirements into a clear system design.  Going forward, I want to spend more time observing how people actually use systems and combine that with prototypes and diagrams. I think getting feedback early and often leads to designs that are more practical, easier to use, and better suited to what users really need.
